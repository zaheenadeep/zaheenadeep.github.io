### কনটেইনার কী?

একটি কনটেইনার হলো একটি *আইসোলেটেড* লিনাক্স প্রসেস, যা একটি
লিনাক্স-ভিত্তিক অপারেটিং সিস্টেমে চলে। এখানে গুরুত্বপূর্ণ শব্দটি হলো
"আইসোলেটেড"। একটি কনটেইনারের নিজস্ব হোস্টনেম, রুট ফাইল সিস্টেম, প্রসেস
আইডি, মাউন্ট পয়েন্ট এবং ইউজার আইডি থাকে, যা হোস্ট OS থেকে স্বাধীন। যদিও
একটি কনটেইনার কেবল একটি লিনাক্স প্রসেস, তবুও এই আইসোলেশন কনটেইনারকে
নিজের ফাইল, ইউজার এবং নেটওয়ার্ক ইন্টারফেসসহ আলাদা অপারেটিং সিস্টেমের
মতো দেখায়।

### কনটেইনার বনাম ভার্চুয়াল মেশিন

একটি কনটেইনার ভার্চুয়াল মেশিনের মতো শোনালে অবাক হওয়ার কিছু নেই---কারণ
অনেক দিক থেকেই সেটাই সত্য। পার্থক্য হলো: একটি ভার্চুয়াল মেশিন একটি
ফিজিক্যাল মেশিনের হার্ডওয়্যার (মাদারবোর্ড, CPU, RAM, NIC সহ) সিমুলেট
করে। অন্যদিকে, একটি কনটেইনার কেবলমাত্র একটি অপারেটিং সিস্টেমের *ইউজার
স্পেস* সিমুলেট করে।

এই ইউজার স্পেস কী? একটি অপারেটিং সিস্টেম দুই অংশে বিভক্ত: কার্নেল এবং
ইউজার স্পেস। কার্নেল উচ্চতর প্রিভিলেজ নিয়ে চলে এবং মেমরি ম্যানেজমেন্ট,
প্রসেস তৈরি এবং ব্লক I/O ম্যানেজমেন্টের মতো মূল কাজ করে। ইউজার স্পেস হলো
OS-এর বাকিগুলো---যেমন `bash`, `ip`, এমনকি Chrome পর্যন্ত। একটি কনটেইনার
কেবল ইউজার স্পেস সিমুলেট করে, কার্নেল নয়, কারণ একটি লিনাক্স প্রসেস
হিসেবে এটি হোস্ট OS-এর লিনাক্স কার্নেল সরাসরি ব্যবহার করতে পারে।

তাই একটি হোস্ট OS-এ একাধিক কনটেইনার থাকতে পারে, কিন্তু তারা সবাই একই
কার্নেল শেয়ার করবে। এজন্য কনটেইনার খুব দ্রুত ডিপ্লয় করা যায়, কারণ
এখানে কার্নেল বা হার্ডওয়্যার সিমুলেশন (ভার্চুয়াল মেশিনের ক্ষেত্রে যেটি
লাগে) করতে হয় না।

### ডকার

কনটেইনার চালানোর একটি জনপ্রিয় উপায় হলো Docker। ডেভেলপাররা অ্যাপ্লিকেশন
কনটেইনারে ডিপ্লয় করার জন্য লোকাল ডেভ এনভায়রনমেন্ট তৈরিতে Docker
ব্যবহার করেন। হোমল্যাব ব্যবহারকারীরাও Docker ব্যবহার করেন Pi-Hole বা
Jellyfin-এর মতো জনপ্রিয় ওয়েব অ্যাপ ডিপ্লয় করতে।

কনটেইনার বাস্তবে কীভাবে কাজ করে তা বুঝতে চাইলে Docker ইন্সটল করতে হবে: -
Linux-এ Docker Engine ইন্সটল করুন এবং পোস্ট-ইন্সটল ধাপ অনুসরণ করুন -
Mac-এ Docker Desktop ইন্সটল করুন (Linux VM ব্যবহার করে) - Windows-এ
Docker Desktop ইন্সটল করুন (WSL ব্যবহার করে)

### ডেমো ১ -- OS তথ্য প্রিন্ট করা

এখন টার্মিনাল খুলে একটি কমান্ড চালাই যা Ubuntu-র ইউজার স্পেস মিমিক করে:

``` shell
docker run ubuntu cat /etc/os-release
```

এই কমান্ডটি একটি Ubuntu কনটেইনার চালায় এবং এর ভেতরে
`cat /etc/os-release` চালায়। কনটেইনারের ভেতরে `os-release` সবসময়
Ubuntu দেখাবে, হোস্ট OS যাই হোক না কেন। কমান্ডটি শেষ হওয়ার সাথে সাথেই
কনটেইনারও থেমে যাবে।

আপনি নিজে দেখে নিতে পারেন:

``` shell
docker ps -a
```

এর আউটপুট প্রায় এমন হবে:

``` shell
CONTAINER ID   IMAGE     COMMAND                 CREATED          STATUS                        PORTS     NAMES
6b8dc0691a1e   ubuntu    "cat /etc/os-release"   2 minutes ago    Exited (0) 2 minutes ago                agitated_ganguly
```

এতে কনটেইনার ID, আপনি কোন কমান্ড চালিয়েছেন, এবং কখন কনটেইনার
থেমেছে---সবই দেখা যায়। একটি র‍্যান্ডম নামও দেওয়া হয়, যেমন এখানে
`agitated_ganguly`।

### ডেমো ২ -- ইন্টারেকটিভ শেল

কিন্তু আগের কনটেইনারটি কমান্ড শেষ হওয়ার সাথে সাথে থেমে গিয়েছিল।
কনটেইনারকে চালু রাখতে, এমন একটি কমান্ড চালাই যা চলতেই থাকে---যেমন
`bash`।

``` shell
docker run -ti ubuntu /bin/bash
```

> যেহেতু আমরা bash ইন্টারঅ্যাকটিভ টার্মিনাল হিসেবে চালাতে চাই, তাই `-t`
> এবং `-i` অপশনগুলো দরকার।

এখন আমরা কনটেইনারের ভেতরে। খেয়াল করুন কনটেইনারের হোস্টনেম ভিন্ন। আপনি
`ls` এবং `cd` ব্যবহার করে ভেতরে ঘুরে দেখতে পারেন এবং `exit` দিয়ে বের
হতে পারেন। `exit` দিলে bash থেমে যাবে এবং কনটেইনারও থেমে যাবে।

### ডেমো ৩ -- ওয়েব অ্যাপ ডিপ্লয়মেন্ট পরীক্ষা

সবসময় `docker run`-এ কমান্ড উল্লেখ করতে হয় না। উদাহরণস্বরূপ:
https://github.com/docker/welcome-to-docker

এই রিপোতে একটি ওয়েব অ্যাপ আছে, এবং সাথে আছে Dockerfile।

গুরুত্বপূর্ণ বিষয়সমূহ: 1. কনটেইনারটি `node-21:alpine` ইমেজের উপর ভিত্তি
করে তৈরি, যা NodeJS-সহ Alpine Linux ইমেজ। 2. Dockerfile-এর শেষ লাইনে
`CMD` দ্বারা একটি `docker run` কমান্ড নির্ধারণ করা হয়েছে, যা HTTP
সার্ভার চালায়। তাই আমাদের `docker run` চালানোর সময় আলাদা কমান্ড দিতে
হবে না।

চলুন কনটেইনারটি কমান্ড ছাড়াই চালাই:

``` shell
docker run -p 8080:80 docker/welcome-to-docker
```

`-p 8080:80` মানে কনটেইনারের 80 পোর্ট হোস্টের 8080-এ ম্যাপ করা। ফলে
ব্রাউজারে <http://localhost:8080> খুলে সার্ভারে প্রবেশ করা যায়।

শেষ হলে Ctrl + C দিয়ে কনটেইনার বন্ধ করতে পারেন।

### ডেমো ৪ -- Docker Compose দিয়ে Joplin ডিপ্লয় করা

এবার একটি বাস্তব উপকারী অ্যাপ ডিপ্লয় করা যাক। `docker run` নয়, Docker
Compose ব্যবহার করবো---যা প্রোডাকশন এবং হোমল্যাবে বেশি ব্যবহৃত।

আমরা Joplin ডিপ্লয় করবো---একটি ওপেন-সোর্স নোট-টেকিং অ্যাপ। তাদের
`docker run` কমান্ড লম্বা এবং বুঝতে কঠিন।

তাই আমরা তার সমতুল্য YAML কনফিগ দিয়ে একটি Compose ফাইল তৈরি করবো।
প্রথমে `joplin` নামে একটি ডিরেক্টরি বানান। তারপর `compose.yaml` নামে
একটি ফাইল তৈরি করে সেখানে কনফিগ লিখুন। ডেমোর স্বার্থে
`/path/to/config`-কে `./config` দিন।

এখন `joplin` ডিরেক্টরি থেকে চালান:

``` shell
docker compose up -d
```

> `-d` অপশন মানে ব্যাকগ্রাউন্ডে (detached মোডে) চালানো।

এটি Compose-এ সংজ্ঞায়িত সার্ভিসটি চালাবে।

<https://localhost:3001> ভিজিট করলে দেখবেন---আপনার নিজের নোট-টেকিং
অ্যাপ!

কনটেইনার বন্ধ করতে চাইলে:

``` shell
docker compose down
```

এটি `./config` ডিরেক্টরি ডিলিট করবে না, তাই নোটগুলো থাকবে। আবার
`docker compose up -d` দিলে নতুন কনটেইনারেও নোটগুলো দেখা যাবে। এটাই
কনটেইনারের জাদু!
